# Исходные условия банка «Стандарт»

Банк хочет привлечь более молодых клиентов. Сегодня большинство клиентов предпочитают отделения. Сайт показывает маркетинговую информацию. В интернет-банке можно проводить платежи и открывать текущие счета с дебетовыми картами. Депозиты и накопительные счета открываются в отделениях с участием фронт- и бэк-офиса. Ставки по кредитам и депозитам банк считает своим конкурентным преимуществом.

## Кто участвует

| Подразделение | Состав и роль |
| --- | --- |
| Сеть отделений | 500 сотрудников в 50 отделениях. Фронт-офис общается с клиентами и работает напрямую в АБС. |
| ИТ | Интернет-банк развивают 10 сотрудников банка и 10 сотрудников подрядчика. В команде АБС 20 человек. |
| Депозитный бэк-офис | 50 сотрудников обслуживают депозитные продукты. |
| Кредитный бэк-офис | 50 сотрудников обслуживают кредитные продукты. |
| Кол-центр банка | 200 операторов. Платформу сопровождают 5 сотрудников подрядчика. |
| Партнёрский кол-центр | 100 сотрудников отдельной компании работают по скриптам, которые передают бизнес-представители банка. |
| Цифровая трансформация розничного бизнеса | 10 человек. |

## Системы сегодня

| Система | Технологии, взаимодействия и ответственность |
| --- | --- |
| Интернет-банк | Монолит подрядчика на ASP.NET MVC 4.5, .NET Framework 4.5 и MS SQL. Для платежей и текущих счетов обращается напрямую к БД АБС. Банк может менять приложение, обновление ядра зависит от подрядчика. Одна группа серверов в основном ЦОД, на случай сбоя предусмотрено переключение в резервный ЦОД. |
| АБС | Учёт операций по счетам и бухгалтерия. Десктопный клиент на Delphi, Oracle, основная логика в процедурах PL/SQL. Разрабатывает банк. |
| Сайт | Собственная разработка на PHP и React.js. |
| Кол-центр банка | Использует функции кол-центра CRM-платформы подрядчика. React.js, микросервисы на Java Spring Boot, PostgreSQL. Развёрнута в банке, поддерживает подрядчик. Java-специалисты команды АБС могут вносить расширения. |
| Партнёрский кол-центр | Внешняя система. Партнёр и поставщик платформы кол-центра банка — разные компании. |
| СМС | Шлюз поддерживает ИТ банка во взаимодействии с внешним телеком-оператором. Оператор отправляет сообщения. |
| Кредитный конвейер | Кредитный бэк-офис обрабатывает заявки из отделений. Коробочное решение на Camunda и Oracle. Подрядчик и специалисты банка могут дорабатывать процессы и обработчики на Java. |
| Кредитный скоринг | Внутренний сервис машинного обучения рассчитывает рейтинг по данным АБС и бюро кредитных историй. Система скоринга разработана банком на Python, предоставляет REST API на Flask, использует PostgreSQL. |
| Бюро кредитных историй | Внешний источник данных с REST API. |

## Что должно измениться

| Горизонт и канал | Ожидаемый результат |
| --- | --- |
| Через 6 месяцев, интернет-банк | Клиент подаёт онлайн-заявку на депозит или накопительный счёт. В MVP бэк-офис может обработать её по существующему процессу. |
| Ближайшая перспектива, сайт | Потенциальный клиент оставляет заявку на депозит. Менеджер кол-центра связывается с ним и рассказывает об условиях. Отдельный срок этого изменения в описании не указан. |
| Через год, интернет-банк и отделения | В интернет-банке депозит или накопительный счёт открывается автоматически. При открытии депозита в отделении участвует только фронт-офис. Банк рассчитывает снизить операционные издержки. |
| Через год, кредит в интернет-банке | Клиент сразу видит, может ли потенциально получить кредит, и может подать заявку. Предодобренное предложение с быстрой заявкой приведено в кейсе как практика конкурентов. |
| Через год, кредит на сайте | Клиент может подать заявку. На этом этапе у банка ещё нет информации о потенциальном клиенте, внешний источник сведений — бюро кредитных историй. |

Для кредитных заявок с сайта и из интернет-банка бизнес ожидает решение в течение одного дня, если данных достаточно. Обычный срок, указанный в кейсе для сравнения, — неделя.

Формулировки пяти отдельных заданий в этом вводном описании отсутствуют. Состав каждого решения определяется соответствующим заданием курса.
