| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     |              |
| F1 | В интернет-банке клиент выбирает счёт, указывает сумму депозита и подтверждает подачу заявки СМС-кодом. После успешной регистрации заявки интернет-банк показывает сообщение «Ваша заявка принята в работу». | В MVP заявку обрабатывает менеджер депозитного бэк-офиса. О подтверждении ставки и об открытии вклада клиент узнаёт из отдельных СМС. |
| F2 | Кредитный и депозитный бэк-офисы должны работать с депозитными ставками в пределах своих полномочий. Кредитный бэк-офис рассчитывает общие ставки, депозитный бэк-офис определяет ставку по конкретной заявке и подтверждает условия в АБС. | Сейчас кредитный бэк-офис передаёт общие ставки в XLS-файле. При расчёте специальной ставки депозитный бэк-офис учитывает оценку риска от кредитного специалиста. |
| F3 | На сайте посетитель видит список доступных депозитов с актуальными общими ставками. В интернет-банке клиент видит также персональные ставки, предложенные ему банком. | Общие ставки доступны в обоих каналах. Персональное предложение доступно клиенту после входа в интернет-банк. |
| F4 | Новый клиент может подать заявку на депозит на сайте, указав Ф. И. О. и номер телефона. Заявка должна быть доступна менеджеру в CRM кол-центра банка. | Менеджер изучает заявку в CRM, звонит клиенту и может предложить особые условия. После звонка клиент проходит идентификацию в отделении. |
| F5 | Новый клиент может подать на сайте заявку на кредит, указав Ф. И. О. и номер телефона. После подачи заявки банк отправляет СМС с приглашением в отделение для идентификации и получения кредита. | Паспортные данные при подаче заявки на сайте необязательны. |
| F6 | Если новый клиент указал в заявке паспортные данные, сайт должен сразу показать предварительное решение об одобрении или отказе по результату кредитного скоринга. | Для оценки нового клиента система кредитного скоринга может использовать только общие данные бюро кредитных историй (БКИ). |
| F7 | Сотрудник отделения должен иметь возможность через АБС продолжить кредитную заявку, поданную на сайте, и увидеть предварительное решение, если оно уже получено. Если клиент ранее не подавал заявку, сотрудник создаёт новую в АБС. | Если клиент оставил на сайте только Ф. И. О. и телефон, сотрудник продолжает ту же заявку, даже если предварительного решения ещё нет. |
| F8 | Сайт и интернет-банк показывают доступные кредиты с актуальными условиями. Если для клиента рассчитано предодобренное предложение, интернет-банк дополнительно показывает ему это предложение с рассчитанной суммой кредита. | Полные условия кредитных продуктов хранятся в Кредитном конвейере. Для показа персонального предложения используется результат ранее выполненного скоринга. |
| F9 | В интернет-банке клиент указывает счёт зачисления и данные для кредитной заявки, затем подтверждает её подачу СМС-кодом. | Требование распространяется и на заявки по предодобренным предложениям. |
| F10 | После подачи заявки по предодобренному предложению банк повторяет скоринг по упрощённой процедуре, если со времени предыдущей оценки изменились сведения, влияющие на решение. | Критерии повторной оценки нужно согласовать с кредитным подразделением. |
| F11 | При изменении статуса кредитной заявки банк уведомляет клиента по СМС. | Перечень статусов, о которых нужно сообщать клиенту, предстоит согласовать с бизнесом. |
| U   | Удобство использования (Usability) |              |
| U1 | Формы подачи заявок на депозит и кредит на сайте и в интернет-банке должны соответствовать дизайн-системе банка, включая принятые цвета и фирменные элементы. | |
| U2 | Клиент должен уметь самостоятельно подать заявку и по сообщению на экране понять, что произошло и какого следующего шага ожидать. | Дополнительное требование. Клиент может принять регистрацию заявки за открытие вклада. На юзабилити-тестировании предложить представителю целевой аудитории подать заявку в прототипе интернет-банка и своими словами объяснить, что произошло и как он узнает об открытии вклада. |
| R   | Надёжность (Reliability)           |              |
| R1 | Сервисы MVP, включая сайт и интернет-банк, должны работать круглосуточно с доступностью не ниже 99,9%. | Бизнес задал этот уровень доступности. Команда интернет-банка считает суточный простой допустимым при нынешнем числе клиентов, но снижение требования для MVP не согласовано. Период измерения доступности нужно уточнить. |
| R2 | При отказе основного ЦОД интернет-банк должен сохранять возможность подачи заявок и выдерживать ожидаемую нагрузку после переключения на резервный ЦОД. | Сейчас интернет-банк работает на одной группе серверов в основном ЦОД. Для проверки R1 нужно измерить перерыв при переключении и проверить подачу заявок под согласованной нагрузкой в резервном ЦОД. |
| P   | Производительность (Performance)   |              |
| P1 | Для подачи заявки на депозит в интернет-банке измерять время от отправки клиентом введённого СМС-кода до отображения результата приёма заявки. Бизнес ожидает отклик за миллисекунды. | Обработка менеджером начинается после приёма заявки и имеет отдельный срок. Для проверки отклика нужно согласовать численный порог, долю операций, которые должны в него укладываться, и нагрузку при измерении. |
| P2 | Предодобренная кредитная заявка из интернет-банка должна поступать сотруднику в Кредитном конвейере без ожидания суточной выгрузки из АБС, чтобы он мог обработать её в тот же рабочий день. | Бизнесу предстоит уточнить предельное время подачи для обработки в тот же день. |
| P3 | Предварительный расчёт кредитных предложений должен выполняться без дополнительной нагрузки на систему кредитного скоринга в рабочие часы. | Скоринг работает круглосуточно. В рабочие часы нагрузка по текущим заявкам повышена. Ограничение касается фонового предрасчёта предложений для будущих заявок. |
| P4 | На сайте и в интернет-банке время от запроса списка продуктов или справочных данных до их отображения клиенту должно укладываться в согласованный предел. | Бизнес ожидает отклик за миллисекунды. Сейчас при платежах загрузка некоторых справочных данных занимает больше секунды. Для приёмки нужно согласовать численный порог и нагрузку, при которой его проверяют. |
| P5 | При росте нагрузки желательно предусмотреть горизонтальное масштабирование сервисов онлайн-подачи заявок и равномерное распределение запросов между экземплярами приложений, серверами и ЦОД. | Кредитный конвейер и система скоринга уже поддерживают горизонтальное масштабирование. Для АБС действует ограничение +R4. |
| S   | Поддерживаемость (Supportability)  |              |
| S1 | Для дальнейшего развития депозитных и кредитных сервисов команда должна документировать путь заявки, ответственность каждой системы и правила обмена данными между системами. | По документации разработчик должен понимать, например, где подтверждается ставка по депозиту и какое событие запускает отправку СМС клиенту. |
| +R  | + Ограничения (Restrictions)       |              |
| +R1 | При проектировании передачи кредитных заявок учитывать фиксированную периодичность существующего обмена между базами АБС и Кредитного конвейера — один раз в сутки. | Учащать обмен по условию нельзя. Для выполнения P2 потребуется иной способ передачи предодобренных заявок. |
| +R2 | Для MVP предпочтительна реализация СМС-подтверждения заявки на депозит силами команды банка без доработки ядра интернет-банка подрядчиком. | Существующий механизм СМС реализован в ядре. Изменения ядра зависят от подрядчика. |
| +R3 | Сайт и интернет-банк должны использовать шифрование при передаче клиентских данных в процессе подачи заявок на депозиты и кредиты. | В зависимости от сценария передаются Ф. И. О., телефон, паспортные данные, сведения о счёте и сумме заявки. |
| +R4 | В новых сценариях просмотра продуктов и подачи заявок предпочтительно избегать прямых обращений интернет-банка к API АБС. | БД АБС уже перегружена и поддерживает только вертикальное масштабирование. Рост трафика в интернет-банке может замедлить выполнение операций банка в АБС. |
| +R5 | При доработке систем предпочтительно использовать технологии, уже применяемые в банке. Новые технологии должны быть совместимы с существующими платформами разработки. При выборе желательно учитывать опыт сотрудников хотя бы с языком программирования. | Например, у банка уже есть опыт работы с MS SQL в интернет-банке и с Oracle в АБС. |
| +R6 | Если для обмена между системами потребуются очереди сообщений, предпочтительно рассмотреть Kafka с учётом дальнейшего развития системы. | Текущая версия платформы интернет-банка несовместима с Kafka. При проектировании обмена потребуется учесть эту несовместимость. |
| +R7 | Если команда выберет микросервисную архитектуру для MVP, изменения архитектуры интернет-банка следует ограничить сценарием открытия депозита. | Переход платежей и других функций интернет-банка на микросервисы выходит за рамки депозитного MVP. |
